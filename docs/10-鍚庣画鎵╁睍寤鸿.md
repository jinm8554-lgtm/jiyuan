# 《裂隙纪元》后续扩展建议

> 本文档面向产品与研发负责人，按「投入小 → 投入大」排序，给出可落地的迭代方向，
> 并标注每项对现有架构的依赖程度。当前版本已完成五大阶段的全部交付目标。

---

## 1. 现状回顾（可扩展的支点）

当前版本已经打好的地基：

| 支点 | 现状 | 意味着什么 |
| --- | --- | --- |
| 配置驱动 | 角色、技能、装备、建筑、区域、节点、任务、剧情、卡池、事件全部落库，GM 后台可改 | **新增内容不需要改代码**，只加配置 |
| 服务端权威 | 概率、保底、战斗结算、奖励、解锁全在服务端 | 客户端无法作弊，可以放心加竞技/排行 |
| 纯逻辑层 | `server/game/` 不依赖 Express，可被测试直接调用 | 容易抽出定时任务、离线批处理或独立服务 |
| 结构化 AI 契约 | 在场角色约束 + JSON Schema 校验 + 违规日志 | 可以安全扩展到更多 AI 场景（如史官、敌将喊话） |
| 备份与迁移 | 迁移幂等、快照可校验可回退 | 支持长期运营的内容版本管理 |

## 2. 短期（1–2 个迭代，低成本高收益）

### 2.1 引导与首日体验

- **新手引导流程可视化**：`gameProfiles.tutorialStep` 已存在但仅记录步数，建议做成显式的 7 步引导
  （建墙 → 招募 → 编队 → 首战 → 领任务 → 见角色 → 掷骰用资源）。
- **首战必赢保护**：首场战斗使用固定低难度编成，保证玩家拿到第一次胜利与掉落。
- **回归补给**：对连续离线超过 3 天的玩家，回城时给一次可选的补给包（复用现有资源发放逻辑）。

### 2.2 战斗可玩性

- **手动战斗的反馈增强**：目前战斗事件已含 `damage` / `heal` / `shield` / `down`，
  建议补上飘字、命中顿帧、克制提示（「火克冰」标签），让克制关系一眼可见。
- **意图预警**：敌方下回合的行动意图提前显示，把「半自动」变成可预判的策略体验。
- **战斗加速与跳过已通关节点**：对已 3 星通关的节点提供「扫荡」（消耗体力直接结算），
  降低重复刷取的疲劳感。
- **阵型深度**：当前只有前/后排，可扩展为 3×2 站位与「护卫/侧击」机制。

### 2.3 角色养成纵深

- **装备强化保底与继承**：`enhanceEquipment` 已有基础，建议加入强化等级继承与失败保护。
- **羁绊剧情解锁**：`bondInteract` 已记录羁绊等级，建议在羁绊 3/5/7 级解锁专属小场景
  （直接复用现有 `storyScenes` 表与播放器）。
- **技能分支**：同一技能在特定等级提供二选一的分支效果（配置化，无需新表）。
- **角色专属任务**：每名 SSR 一条个人任务线，复用 `quests` 表并加 `charKey` 关联字段。

### 2.4 运营与社交

- **限时活动框架**：`recruitPools` 已有 `openAt` / `closeAt`，可扩展为通用「活动」表，
  统一管理限时关卡、限定卡池、登录奖励。
- **公会 / 骑士团**：轻量社交（成员列表、共同任务进度、互助赠礼），不做实时聊天以控制成本。
- **排行榜**：区域控制度、最高战力、最快通关等榜单，服务端只需聚合现有数据。
- **分享图生成**：把角色卡 + 战绩渲染为可分享图片（服务端生成，避免前端泄露数据）。

## 3. 中期（3–6 个迭代，需要新模块）

### 3.1 剧情与叙事

- **分支剧情与结局**：当前 `profileStoryFlags` 已能记录选择，建议加入
  「关键选择影响章节走向」的结构（如：谈判派 vs 武力派影响第 4–6 章场景集）。
- **动态事件系统**：领地事件已配置化，可扩展为「按资源短缺/民心上限/时间触发的自动事件流」。
- **多结局与二周目**：通关后保留部分成长开启新周目，提高长线留存。

### 3.2 战斗系统扩展

- **羁绊连携技**：特定角色组合（如艾德里安 + 格蕾塔）解锁合击技能，增强收集与编队动力。
- **Boss 机制战**：多阶段 Boss、部位破坏、机制破解（配置化到节点敌人上）。
- **爬塔 / 无尽模式**：复用战斗引擎，用连续节点 + 递增难度实现，奖励用兑换商店承接。
- **装备套装效果**：`SET_BONUSES` 已存在，建议补齐 3–4 件的成套特效与可视化提示。

### 3.3 领地经营深化

- **建筑专精**：同一建筑可选择两种专精方向（如工坊→兵器 / 护甲），产生不同产出与解锁。
- **地块与扩建**：城堡外围地块解锁，带来新的建筑位与装饰，强化「重建领地」的主题。
- **民心与声望系统**：把 `renown` 扩展为多维（民心、军心、学术声望），影响可招募角色与事件走向。
- **贸易网络**：当前贸易按节点产出，可扩展为路线（城—村—要塞）与商队护送事件。

### 3.4 AI 能力扩展（在既有契约内安全扩展）

- **新场景**：史官编年（自动生成战报）、敌将喊话、酒馆传闻、任务引导，
  全部复用现有「在场角色 + JSON Schema」契约。
- **角色长期记忆**：`aiConversations` 已存消息，建议加入「长期记忆摘要」表，
  让角色记住数周前的关键承诺与冲突（注意与剧情状态一致性校验）。
- **多角色冲突与调解**：允许两名立场冲突的角色互相反驳，由玩家裁决，直接影响羁绊数值。
- **模型分级路由**：日常对话用轻量模型，关键剧情节点用高质量模型，控制成本。
- **人工审核台**：把违规日志接入后台审核队列，形成内容安全闭环。

## 4. 长期（6 个迭代以上）

### 4.1 内容生态

- **关卡编辑器**：让策划可视化编辑节点、敌人编成、掉落与剧情绑定，导出为配置 JSON。
- **Mod 友好配置**：把 `server/game/data/*` 抽为可外部加载的配置文件，支持内容包。
- **多语言**：当前文案为中文，建议抽出 i18n 词条表，优先支持英文与日文。

### 4.2 平台化

- **账号体系升级**：当前依赖 Manus OAuth，如需要独立发行可加入邮箱/第三方登录（保留 OAuth 作为一种方式）。
- **跨端**：移动端浏览器体验已适配，可进一步用 Capacitor 打包为原生 App。
- **离线单机模式**：把 `server/game/` 纯逻辑层移植到本地，支持无网试玩前两章。

### 4.3 技术债与架构演进

| 方向 | 说明 | 触发条件 |
| --- | --- | --- |
| 引入 job 队列 | 把资源结算、批量备份、AI 日志归档移出请求路径 | 玩家数 > 1 万 或 出现请求超时 |
| 读写分离 | 招募/战斗写入密，排行榜/地图读取可走只读副本 | 数据库 CPU 持续 > 70% |
| 缓存层 | 配置表（角色/技能/世界）变化少，适合进程内缓存 + 版本号失效 | 配置读取成为瓶颈 |
| 事件溯源战斗 | 战斗日志改为事件流存储，便于回放与反作弊校验 | 需要竞技对抗玩法时 |
| 分表 | `aiCallLogs` / `battles` 按时间分表或转冷存储 | 单表 > 千万行 |

## 5. 商业化建议（在现有框架内）

| 方向 | 落地方式 | 注意事项 |
| --- | --- | --- |
| 会员订阅 | `users.membership` 字段已存在 | 只提供便利与外观，不卖数值优势 |
| 抽卡星辉 | 已有 `aether` 货币与卡池成本配置 | 概率与保底必须公开公示（已实现） |
| 通行证 | 用活动表 + 任务表组合实现 | 奖励可预期，不制造焦虑 |
| 外观 | 城堡装饰、角色服装（**必须符合全年龄向要求**） | 严禁色情服装与身体羞辱 |
| 广告 | 不建议；与叙事氛围冲突 | — |

> 全年龄向是本项目的硬性定位：任何商业化设计都不得引入成人向内容或赌博式诱导机制。

## 6. 内容生产建议（新增角色 / 区域的操作路径）

当前架构下新增内容**不需要写后端代码**：

```
1. 准备立绘（3:4）与头像（1:1）
2. python3 scripts/optimize-assets.py   → 压缩
3. manus-upload-file --webdev ...       → 上传并获得 /manus-storage/ 路径
4. GM 后台 → 角色库 → 新建角色 → 填写全部资料字段 → 上传立绘/头像
5. GM 后台 → 招募池 → 把角色加入卡池（或设为限定）
6. 状态设为「已发布」→ 客户端立即可见
```

新增区域同理（GM 后台 → 世界地图 → 新建区域 / 节点 / 敌人编成与奖励）。
**保持角色卡的「性格 / 个人目标 / 背景 / 关系」字段完整**，AI 互动的质量直接取决于这些字段。

---

## 7. 优先级建议（若只能做三件事）

1. **补齐新手引导与首战体验** —— 决定次留，投入最小，收益最大。
2. **战斗反馈与克制可视化** —— 决定核心战斗是否「看得懂、打得爽」，直接影响口碑。
3. **羁绊专属剧情 + 连携技** —— 把角色收集与战斗策略真正连起来，是长线留存的发动机。
